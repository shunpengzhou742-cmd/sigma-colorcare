# SIGMA ColorCare — 员工邀请与自动激活测试计划

> 目的：在部署 Firestore Rules 前验证邀请流程和权限边界。当前测试尚未执行，不能视为线上已启用。

## 测试环境
- 使用 Firebase Emulator Suite 的 Authentication 与 Firestore。
- 使用独立测试管理员账号和两个独立 Google 测试账号。
- 不使用真实员工资料，不修改线上 Firestore。
- 每次规则变更后重新运行全部用例。

## 必须通过的用例

| 编号 | 操作 | 预期结果 |
|---|---|---|
| INV-01 | 有效管理员创建包含修色部门的邀请 | 允许创建；邀请有效期不超过 24 小时 |
| INV-02 | 普通员工尝试创建邀请 | 拒绝 |
| INV-03 | 已验证 Google 账号使用有效邀请，事务同时消费邀请并创建员工资料 | 两项写入同时成功；员工状态为 active |
| INV-04 | 第二个 UID 使用同一邀请 | 拒绝；不能创建第二份员工资料 |
| INV-05 | 使用过期邀请 | 拒绝 |
| INV-06 | 使用不存在或随机猜测的邀请 ID | 拒绝 |
| INV-07 | 使用非 Google 登录方式领取邀请 | 拒绝 |
| INV-08 | 员工客户端伪造 roleType=0、status=admin 或 specialRole=true | 拒绝 |
| INV-09 | 员工客户端把邀请中的部门改成其他部门 | 拒绝 |
| INV-10 | 员工尝试读取其他 UID 的 employees 文档 | 拒绝 |
| INV-11 | 员工尝试更新或删除自己的员工资料 | 拒绝 |
| INV-12 | 管理员 UID 打开员工邀请链接 | 不消费邀请、不创建员工资料 |
| INV-13 | 员工只获授权部门 1 | 仅显示修色入口 |
| INV-14 | 事务只写邀请、不创建员工，或只创建员工、不消费邀请 | 整个事务拒绝 |

## 通过标准
- 所有用例均符合预期。
- Firebase Emulator 中 Rules 编译无错误。
- 同一邀请并发领取时，只允许一个 UID 成功。
- 线上部署前，先向负责人展示最终规则文件和变更内容，并取得明确确认。

## 当前限制
- 本计划尚未在 Emulator 执行。
- GitHub 中的 firestore.rules 是候选规则，不代表 Firebase Console 中线上规则已经改变。
- 线上员工邀请功能必须等规则验证并经负责人确认部署后才能使用。
